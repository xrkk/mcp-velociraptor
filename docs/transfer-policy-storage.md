# Transfer policy and task store (internal API)

`velo_transfer.policy` authorizes local paths and binds a policy to an explicit VM observation. `velo_transfer.storage` persists caller-owned task JSON under that policy's work root. Neither module starts the bridge, probes a VM, transfers bytes, interprets terminal phases, runs workers, deletes evidence, or grants global COMPLETE.

## Policy

`load_policy(path=None, *, observation=None, guest=True, verify_windows_acl=None) -> PolicyStatus` reads only the explicit path or `VELOCIRAPTOR_TRANSFER_POLICY`. An absent or empty path returns `PolicyStatus(enabled=False, reason="not_configured", policy=None)`. A nonempty invalid path raises `TransferContentError(code)`; the caller may keep old bridge tools running while denying new transfer actions. The policy file is limited to 65,536 bytes before JSON parsing, is read with duplicate-key/NaN rejection, and must be a regular non-link file. A changed file identity or SHA-256 fails later `Policy.revalidate()`.

The exact `velo.transfer.policy.v1` JSON keys are `schema`, `policy_id`, `expected_vm_uuid`, `read_roots`, `write_roots`, `work_root`, and `limits`. `policy_id` is a 1–128 character ASCII identifier; UUID is canonical lower-case hyphenated text. Roots are nonempty explicit absolute paths to existing real directories. `limits` has positive integer `max_files`, `max_metadata_bytes`, `max_package_bytes`, `max_state_bytes`, and `max_duration_seconds`, plus optional positive `max_chunk_bytes`, plus nonnegative integer `max_logical_bytes` and `min_free_bytes`. Booleans are not integers. Maximum duration is seven days. Omitting `max_chunk_bytes` uses a 1 MiB raw chunk default; the configured maximum is adjustable and cannot exceed `max_package_bytes`; no fixed single-file limit is introduced. The caller must pick a finite, unexpired monotonic deadline within the configured duration; both the content-budget factory and task store enforce this constraint and can pass a cancellation callback to `Policy.content_budget`.

`observation` must be an explicit trusted `{"os_name":"Windows","vm_uuid":"..."}` for the default guest gate. No OS or UUID is inferred from a backend client ID. A host caller may explicitly set `guest=False` and supply its trusted observed VM identity; this does not authorize a guest on non-Windows. Tests inject observations; integration must obtain actual guest OS/UUID/boot facts separately. The policy file and work root must not be group/other writable on POSIX, and every ancestor must have a trusted owner (root or the effective user); writable ancestors require sticky-directory protection for a trusted-owned child. On Windows, `verify_windows_acl(path, kind)` must return literal `True` for policy and work; the provider must inspect actual protected ACLs and account write rights. This module does not implement that production provider, so Windows integration remains gated. Stage ACL verification is separately required by the content layer.

`Policy.resolve_local(path, purpose, allow_missing_leaf=False)` requires `purpose=read|write|work`. It rechecks policy hash/identity and saved root identities, requires an absolute lexical path below a matching root, rejects links/reparse points in all existing ancestors, and permits only the final missing component when requested. It never dereferences a remote `expected_destination`; that remains a logical descriptor in `protocol.py`. The caller must recheck before each sensitive use, because same-account or administrator interference and paths changing after validation remain outside this function's atomicity guarantee.

Example policy data (replace paths and UUID with deployed, protected values):

```json
{"schema":"velo.transfer.policy.v1","policy_id":"transfer-1","expected_vm_uuid":"12345678-1234-1234-1234-123456789abc","read_roots":["/existing/read"],"write_roots":["/existing/write"],"work_root":"/existing/private-work","limits":{"max_files":100000,"max_metadata_bytes":16777216,"max_logical_bytes":1099511627776,"max_package_bytes":1099511627776,"min_free_bytes":1073741824,"max_chunk_bytes":1048576,"max_state_bytes":1048576,"max_duration_seconds":3600}}
```

## Store

`TaskStore(policy, deadline_monotonic=None)` uses `<work_root>/.transfer-writer.lock` and `<work_root>/tasks/<transfer_id>/state.json`. `transfer_id` matches the protocol's safe ASCII ID. The work root must already exist and be private; the store creates only its fixed private `tasks` and per-task directories. The lock file is never unlinked by the store. Hold `with store.writer():` across each create/load/save transaction. A second process receives `writer_busy` immediately; process exit releases the OS lock. PID and random owner ID are recorded for later worker ownership checks, but neither PID alone nor this store proves worker ownership. Do not delete or replace the lock path while a writer is active.

`binding` is exactly `request_digest` (64 lowercase hex), `policy_id`, `vm_uuid`, `boot_identity`, `vm_epoch`. The VM UUID must equal the policy's expected VM UUID. It fixes task ownership before package identity is known; later full K and terminal snapshots can live in `state`. The store does not validate semantic agreement of those objects with real bytes or the pure terminal protocol. `create(transfer_id, binding, state)` requires the lock, writes revision 0, and returns an existing snapshot unchanged for the same ID/binding. Different binding conflicts even after tombstone. `load(transfer_id, binding)` validates ownership, schema, revision, canonical JSON, SHA-256, size and file type without changing disk; it returns a deep copy. `save(transfer_id, binding, expected_revision, state)` requires the lock and exact CAS revision, then returns a deep copy of the next revision. Caller state may hold `GuestTerminal.snapshot()`, stage/worker/package identities, publish intent, receipts and tombstone. The store does not advance phases or remove any task/source/published directory.

Each envelope is canonical JSON with exactly `schema`, `transfer_id`, `binding`, `revision`, `state`, `owner`, `sha256`; the SHA-256 covers the other fields. Values must be finite JSON, maximum nesting 32 and maximum 10,000 nodes, and encoded bytes cannot exceed `max_state_bytes`. Size, depth and node limits are checked incrementally before copying or serializing the state. Invalid new input is rejected before creating its task directory, so correcting that input can reuse the same ID; an interrupted actual create still requires reconciliation. Reads request at most that limit plus one byte and reject overlarge files before parsing. The SHA-256 detects accidental corruption, not an active writer with filesystem access or cryptographic authentication.

Writes use a new private same-directory `.state-*.tmp`, full write and file fsync, then atomic replacement of this store's own `state.json`. POSIX syncs the task directory; Windows uses `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)` and file fsync, but real Windows power-loss durability is not established until platform tests. A fault after replacement may produce `storage_durability_unknown` with observed revision; read back under the writer lock before retrying. A fault leaving an old intact revision produces `storage_write_failed`; corrupt/unreadable or absent state produces `storage_reconcile_required`. Never recreate an empty task directory after an unknown create result without reconciliation. These replacements concern metadata only and do not replace final evidence directories.

## Stage registration sequence

After fixing the request/binding, persist a stage name and intended destination with `store.save`. Hold the writer lock, call content-layer `prepare_staging(..., register_stage=callback)`, and in the callback load the saved intent and CAS-save the exact stage/parent identities before returning literal `True`. Only then call `unpack_bundle(..., staging=returned_stage)`. `tests/test_transfer_storage.py` runs this sequence with a benign temporary tree. A crash between stage creation and callback leaves only the caller-chosen path; recovery must compare its real identity with persisted intent and must not scan or delete unknown directories. Later, persist the pure protocol `publish_intent` before content-layer atomic publication and its receipt after real verification. Global completion remains the host coordinator's responsibility.

Windows ACL provider, guest identity observation, worker ownership, transport and VM execution are integration prerequisites outside this module. Local tests simulate observation and do not establish deployed Windows identity or ACL safety.
