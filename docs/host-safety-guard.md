# Uninstalled host safety checkpoint guard

`tests.host_safety_guard` is a host-only, fail-closed controller for **one newly named safety checkpoint of one approved VM**. `tests.host_safety_units` renders one per-attempt systemd service/timer and contains a separate, root-only installer. Neither module is imported by the MCP runtime, installed, enabled, or invoked against real `vmrun` by this commit. The code is experimental until a native VMware/systemd/guest rehearsal succeeds.

The external manifest fixes the attempt UUID, VMX path/SHA/device/inode, canonical path/SHA, safety name `Snapshot G14-SAFETY-<UUID>`, exact `/usr/bin/vmrun` path/SHA, controller/installer/interpreter SHA and install paths, one UTC deadline, protected state path, 32 GiB minimum free space, per-command timeout ≤90 seconds, and ≤8 mutating actions. A *distinct* protected decision file is named by the manifest and bound by byte SHA. Its exact `APPROVED` object binds VMX/safety name/actions and the manifest's code, interpreter, unit paths, budget, and canonical identity. The production controller requires root, root-owned 0600 manifest/decision, plain no-symlink paths and exact code/interpreter identities on each invocation. Test mode is fixed to an isolated fake adapter under `tests/`; its manifest and state explicitly carry `test_mode=true` and cannot be reused as production state.

`check` is read-only and does not create a state directory. Installation is an explicit separate command requiring root and a distinct decision file. It validates all inputs, available target paths, ownership, code hashes, VMX/canonical, and rendered units with `systemd-analyze verify` **before** writing any production artifact. It uses exclusive creates and fsync, cleans only files it created on a preactivation error, then daemon-reloads and enables only its own timer. An unknown outcome after enable starts is retained for inspection instead of blindly removed. Review rendering adds an impossible `ConditionPathExists` and is never installable authorization. The timer has an absolute UTC calendar trigger, a one-minute boot check, `Persistent=true`, and a 900-second oneshot bound; the controller independently checks the deadline.

The durable state has one persistent flock, pinned owner PID/start tick/boot/exe/argv/cgroup, exclusive event files and fsynced atomic state. A deadline takeover may signal only an exact pinned controller with no pending action/child; it never signals a process group or an unknown owner. Every mutating `vmrun` has an intent before launch, a budget count, a captured response, and VMX identity checks before and after. Timeout/nonzero/changed identity leaves an unknown operation and bars retries. Checkpoint creation ends `CREATED_UNQUALIFIED`; one stop/revert/start rehearsal ends `HOST_RESTORED_PENDING_GUEST`. Qualification needs a separately approved, byte-pinned guest re-entry receipt outside the controller state directory; arming requires that qualification. Deadline recovery can revert **only the new safety name**, once, then returns to pending guest re-entry. `COMMITTED` requires another separate decision pinning a health/epoch8 receipt and actual canonical byte/shape check. Neither a guest JSON file in the state directory nor a fake result can independently qualify production.

The controller never selects historical snapshot names, changes the host canonical, runs a guest collection, or authorizes a business restore. A host snapshot does not restore the host canonical file. A pending/unknown operation, missing image, `.next`, VMX/canonical drift, owner uncertainty or missing external approval is a refusal, not success. The guard assumes root and approved collector/decision authors are trusted; it does not prove VMware effects or the truth of guest health claims. The external approver must validate guest originals and service/frontend/secret-file re-entry before producing the approval file. Actual VM operation also requires the separate one-window approval described in the T015 result package.

Run the isolated regression with `.venv/bin/python -m unittest tests.test_host_safety_guard -v`. Its fake executable, OS subprocesses/flock/signals/fsync and review-only `systemd-analyze verify` run on the host without changing systemd or any VM. The native gate still includes exact manifest and decision creation, real VMX/space/ACL preflight, one safety checkpoint creation and recovery rehearsal, systemd persistence/boot behavior, guest re-entry and independent inspection of all receipts. Do not interpret this code commit as permission to install or perform those actions.

## One-window safety rehearsal terminal state

`finish-rehearsal` is separate from the epoch8 business `commit`. It requires `ARMED`, a new root-protected guest health receipt with independent management re-entry/health/secret-file original hashes, and an external decision with exact `SAFETY_REHEARSAL_FINISH_ONLY` scope pinning that receipt's byte SHA. It rereads the manifest-pinned epoch7 canonical bytes, requires epoch 7 / the separately approved phase and active snapshot name, and never changes that host file. It writes an O_EXCL/fsynced safety finish receipt before the terminal state. Only `SAFETY_REHEARSAL_COMPLETE` with its matching receipt sets `timer_disarm_eligible=true`; the future operator may then disable **this attempt's exact timer** under the separate approved window. This code does not run `systemctl disable`. A crash after receipt creation but before the state update makes deadline return `FINISH_PENDING_RECONCILIATION` without revert; repeating the same approved `finish-rehearsal` may close it. Repeated deadline or finish calls after completion are idempotent, and business `commit` is refused.

## Recovery transaction crash boundary

A restore now has its own durable `restore_transaction` with an exclusive ID, purpose, checkpoint, pre-action budget and stage. The controller writes `BEFORE_STOP` before the first mutating call, then records stop/revert/start response and stage transitions through `BEFORE_REVERT`, `BEFORE_START`, and `READBACK_CONFIRMED`. The final atomic state write sets both `HOST_RESTORED_PENDING_GUEST` and transaction `COMPLETE`. A crash after any response but before its pending flag or stage is cleared leaves a non-complete transaction. On restart, repeated deadline/qualify and held-lock takeover refuse a second revert and mark or report `INDETERMINATE`; operators must inspect raw VMware and guest state. An earlier completed qualification transaction is retained in state history when a later deadline recovery begins. Fake subprocess tests inject process exits at each of ten transaction boundaries, then run another controller process to confirm no replay.

Snapshot tree readback accepts VMware's tab-indented descendant names while checking the declared count and exact safety name. After revert, the controller rereads the running VM list: it starts the target only when absent, and records the already-running branch without issuing a duplicate start. Both branches stay inside the same durable restore transaction. The actual power behavior of this VMware installation remains a native rehearsal gate.

On this host `/usr/bin/vmrun` is a symlink to `/usr/lib/vmware/bin/appLoader`. A production manifest must bind that exact target and the target executable's SHA; the controller and installer verify the link text, symlink-free target chain, executable mode, and bytes before use. Test mode continues to require its plain fake executable.
