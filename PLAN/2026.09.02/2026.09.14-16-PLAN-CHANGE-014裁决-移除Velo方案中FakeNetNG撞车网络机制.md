# PLAN-CHANGE-014 裁决记录：移除 Velo 方案中与 FakeNet-NG 撞车的网络域机制

创建日期：2026-09-14（Asia/Shanghai）。性质：用户直接指示的方案变更（"把 velo 里跟 fakenetng 撞车（机制、功能）的都去掉"）；本文记录评估、裁决内容与实施。旧文本按各文档既有覆盖惯例保留为被覆盖历史，不逐行删除。

## 评估依据（全部实测）

1. **拓扑事实**：目标 VM（DESKTOP-3FI41GR）默认网关与 DNS 均为 192.168.204.2（VMware 网关），hosts 为空，无任何路由经 FakenetNG VM；FakeNet-NG 位于独立 VM（Win10(MalBox)-FakenetNG），不在 Velo 流量路径上。**当前运行时零冲突；撞车全部为设计层的机制/功能重复。**
2. **机制撞车**：netsh trace scenario provider 与 WFP 重定向 callout 是已知互毁组合（FakeNet-NG 的机制基座）。本 VM 上 netsh trace 亦实测异常：经 client execve 启动的 trace 在 Flow 完成即死（0.04 秒证据）、场景 trace 杀全 P05 进程树。
3. **功能撞车**：流量捕获（PacketCapture）与全窗口流量观测属网络域工具职责，与 FakeNet-NG 的定位重复。
4. **非撞车裁定**：localhost:8000/public 工具本地服务是 Velociraptor 原生机制（serve_locally）且为当前零公网不变量的唯一执行层（FakeNet-NG 不在路径，无替代），**保留**；PC006 防火墙边界属防火墙域，**保留**。

## 移除集（本次裁决）

1. **PacketCapture netsh-trace 链整体移除**：P05 四链→三链（Autoruns/Triage/KillProcess）；P06 资源资格的 PacketCapture 两条链移除（13 admission→11）；P06 逐工具与覆盖集改为 **129 实测 + 1 登记排除**（Windows.Network.PacketCapture 保留在 130 注册面、保留 tools/list 计数 130 不变，排除原因=网络抓包职能划归 FakeNet-NG 域且本 VM 上 netsh 机制异常），覆盖关系 **650→645**；五场景 JSON 与 coverage manifest 同步重构。
2. **etl2pcapng 依赖移除**：其唯一用途是 PacketCapture 的 ETL→PCAPNG 转换；依赖清单 3→2（Autorun_386/Autorun_amd64 保留），依赖验收谓词同步修订。
3. **完整网络窗口门降级**：P05 §264/§154 的 network_observations 全窗口硬门移除；已建的 Kernel-Network ETW 观察保留为**可选支撑证据**（非门）；"零公网来源请求"保留为设计不变量，其执行层为 serve_locally 架构与已移除的上游探针（PC-013 推论），不再要求全窗口证明。
4. 遗留 wfp.etl/wfp.xml 为历史实验残件（已在恢复前备份），不再进入任何验收面。
