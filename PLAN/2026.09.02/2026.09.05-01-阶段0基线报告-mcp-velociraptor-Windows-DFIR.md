## 1. 结论摘要

P01 已在用户指定的单台 Windows 10 验收 VM 中建立并验证 Velociraptor 0.77.2 本地测试底座，创建并原子激活安装后内存快照 `Snapshot 184-Velociraptor-MCP测试基线`。今后本 workflow 的正常恢复目标只有该快照及其 `Snapshot100.vmsn` checkpoint；旧 `Snapshot 183-FakenetNG测试专用` 只保留为需要用户新授权的人工回退点。

真实 root Org 中共有 202 个 `Windows.*` artifact 定义，其中 `CLIENT=167`、`CLIENT_EVENT=33`、`SERVER=2`。需求附录 A 的 118 项全部存在且全部为 `CLIENT`，允许集合与依赖矩阵双向差集均为零，依赖分类没有 `unknown`。其中 116 项当前无声明外部依赖；`Windows.Sysinternals.Autoruns` 需要预缓存 Sysinternals 工具，`Windows.Network.PacketCapture` 需要运行时访问外部下载地址，当前二者均不满足，必须只暂停各自工具，不能静默删减或临时联网。

当前仓库的 gRPC、VQL 和配置解析思路可以继续复用；collection、Flow、Hunt 和 file 需要局部重构或补齐；现有 stdio 入口在已安装 `mcp==2.1.1` 下因 SDK 将 `FastMCP` 更名为 `MCPServer` 而在 initialize 前导入失败。该失败已由空 stdout、明确 stderr 和退出码真实定性，归 P02 的依赖锁定/兼容修复，不构成 P01 环境阻断，也不支持整体重写。
