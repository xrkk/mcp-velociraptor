### SELF-P01-004｜新快照若创建即替换会留下不可恢复窗口

- 风险：安装不完整、快照无内存或恢复后API失效时，直接把Snapshot 184设为默认会丢失唯一已验证恢复入口。
- 对应：第4.1、4.5节及ACC-P01-010。
- 证据：用户关于安装后快照的明确要求和既有checkpoint经验。
- 修改：固定“零匹配 -> 安装/API/唯一client门 -> 一次snapshot -> 唯一性/.vmsn门 -> 完整revert/marker/vmware-x/hostname/API复验 -> 原子激活”。验证前保留Snapshot 183为活跃目标；失败不激活、不删除旧快照。
- 结论：已闭合。

### SELF-P01-005｜同机测试部署可能越界监听或泄露高权限身份

- 风险：Instant server/API或admin API identity若暴露到非loopback，恶意代码测试环境的攻击面扩大；config若回传会泄露私钥。
- 对应：第4.4、7章、ACC-P01-010。
- 证据：官方API使用mTLS且API身份权限强；用户仅授权本VM本地测试用途。
- 修改：所有服务仅接受loopback；发现外部监听即停止本workflow PID并失败；server/client/api config、datastore/writeback均不得离开guest，host证据只保留脱敏路径、哈希和查询摘要。
- 结论：已闭合。

### SELF-P01-006｜依赖安装与P02锁版职责可能冲突

- 风险：P01修改requirements或提前裁决版本会侵入P02。
- 对应：IMP/ACC-P01-010、P02入口。
- 证据：总纲规定P01记录实际版本、P02负责锁定。
