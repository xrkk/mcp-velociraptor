### 3.2 P02冻结决定

1. SDK方向唯一采用 MCP 2.1.1 `MCPServer`，不降级或并存 FastMCP v1；这是对已安装官方SDK的最小局部迁移。
2. 公共模块只包含被 P03/P04 同时需要的模型与服务边界，不拆分成包、不建插件/profile/策略层。
3. root Org 在公共 API 中没有可选参数；内部调用统一传 `None`/空 org context。client 第一次 endpoint 操作才解析，不作为 server ready 前置。
4. client候选只接受 `os_info.system` 精确不区分大小写为 Windows 的全部真实候选。0个抛 `CLIENT_NOT_FOUND`，超过1个抛 `CLIENT_NOT_UNIQUE`；不按LastSeen、hostname或列表顺序猜测。
5. 缓存仅在当前 Python 进程实例内。endpoint操作失败后，生产适配器才以同一root Org执行精确client_id存在性只读查询；该查询成功且恰好0行时抛专用`CachedClientIdNotFound`。查询失败/超时、返回1行或多行、普通gRPC错误和collection失败都不匹配该谓词、不清缓存。P01后补Spike已证明现有ID返回1行、确定不存在ID返回0行，证据为`Logs/P02/wf-01a05d1d-p02/spike-client-id-existence.json`。命中后清缓存、重新解析并把原操作最多重试一次。
6. 成功返回 `CallToolResult(content=[], structuredContent=<对象>, isError=false)`；失败返回同形态且 `isError=true`。工具返回注解使用`Annotated[CallToolResult, <该操作的成功模型>]`或SDK 2.1.1等价机制发布准确成功outputSchema；错误结构由`isError=true`转录单独验证。禁止 JSON 文本兼容副本。
7. P02稳定错误 code、触发、重试和脱敏规则以第4.4节为唯一决策表；后续如出现无法映射的真实新错误，必须回流 P02，而不是复用相邻code隐藏语义。
8. 分页 cursor 采用无秘密的规范编码`v1:<十进制非负offset>`；0只能编码为`v1:0`，正数不得有前导零，offset上限为`2147483647`，总长度最多13个ASCII字符。格式、负值、前导零、超长或超上限均为`INVALID_ARGUMENT`。cursor只表示本次请求选定结果集的偏移，不携带或证明签发来源。P04每次以显式flow_id/source和唯一目标重新验证对象及结果源；source省略时按P04的多source顺序解释全局偏移。调用方须保持同一分页链的flow_id/source不变；相同cursor文本用于其他合法结果集时按该请求上下文解释，不能承诺识别它是否来自另一Flow/source。P02不虚构后端cursor，不新增会话游标登记簿、签名或隐藏目标切换。
9. 字节限制按最终`structuredContent`候选对象计算，唯一序列化口径为`json.dumps(value, ensure_ascii=False, allow_nan=False, sort_keys=True, separators=(",", ":")).encode("utf-8")`。限制函数必须接收完整成功模型/构造回调和待分页data，不能只看rows。它按原顺序取最多page_size行，再搜索不超过245554 bytes的最大非空前缀；单行连同完整包络仍超限时返回`ROW_TOO_LARGE`。存在未返回行时`truncated=true`且`next_cursor`指向首个未返回行；完全返回时为false/null。
10. 当前旧78工具的迁移不属于P02。P02的ACC-P02-002/003只裁决将被P03/P04直接调用的生产公共构件及其真实MCP注册路径，不宣称旧78工具已经满足最终产品schema；总纲ACC-003/008中“全部工具”的终检明确由P06执行。专用fixture必须直接注册同一个生产result/TargetContext构件，不能复制实现。真实bridge另执行SDK 2.x initialize/tools/list、一个只读server查询和一个代表性endpoint tools/call，证明SDK迁移没有破坏过渡工具；该旧工具转录只证明迁移兼容，不作为新结构化契约通过证据。
11. 正式传输固定为MCP SDK 2.1.1的有状态Streamable HTTP，端口28790、路径`/mcp`；测试传输固定为stdio。传输选择只能发生在调用同一个`MCPServer`注册实例的最终启动函数，禁止构造第二个server或重复注册工具。
12. 正式配置必须显式提供guest host-only监听地址和部署者Bearer token；`0.0.0.0`、`::`、空token、非28790端口、非`/mcp`路径均在打开socket前失败。地址是否确属目标host-only网卡由P05安装时实测，P02只提供可注入验证接口。
13. HTTP请求门使用`Authorization: Bearer`，token只从进程环境/受保护启动配置读取，不生成、不回显、不写日志；比较使用恒定时间语义。无/错scheme或token均返回401且不进入MCP handler。
14. MCP SDK DNS rebinding保护保持开启；allowed_hosts由配置的准确IP:28790生成。官方非浏览器SDK可以不发送Origin；出现Origin时只有显式allowed_origins值可通过。错误Host或未允许Origin在进入MCP handler前拒绝。
15. 正式HTTP采用单进程、`stateless_http=False`以保留P06同一会话连续性；不启动多worker。若SDK实测无法保持会话或实际客户端不能发送Authorization头，按FB-P02-005停止并回流，不降级认证。
16. HTTP进程每次启动时生成一个不可预测、非秘密、仅用于证据关联的`server_instance_id`；同一进程生命周期内保持不变，进程重启必须变化。所有已经通过请求门并由MCP HTTP入口产生的响应都携带准确响应头`X-MCP-Server-Instance: <server_instance_id>`；该值不得由客户端提供或覆盖，不替代Bearer、PID或进程创建时间，也不得包含主机名、路径、token等敏感信息。P05把该响应头与guest只读服务观察中的PID、进程创建时间及可执行文件SHA-256作哈希join，P06只消费这一身份语义，不重新定义。

## 4. 公共接口与数据契约

### 4.1 结果模型

公共成功基类只固定真正全局字段：

- `operation: str`：调用语义名；
- `status: str`：来自后端或明确的server查询完成状态；不得为不存在的Flow/Hunt伪造状态；
- `warnings: list[str]`，默认空数组。

在此基类上按语义组合互斥/可组合模型：`DataResult`增加必需`data`与仅分页操作需要的`pagination`；固定启动使用的`FlowReferenceResult`增加必需且真实的`flow_id`和required非空真实`state`；`HuntReferenceResult`增加必需且真实的`hunt_id`，start_hunt组合`flow_id`时同时required非空`flow_state`，而`state`仍表示Hunt状态。四个新增Flow状态字段只适用于固定启动，动态工具既有status不变。序列化必须省略不适用字段，不得输出无意义`null`。正常空结果使用空数组或语义明确的空对象，并保持`isError=false`。

`ErrorResult` 必需字段：`code`、`message`、`retryable`、`details`。`details`只含可公开复核字段，不包含证书、私钥、token、完整连接串或用户专属配置路径。`isError`只由MCP `CallToolResult.isError`承载，不在structuredContent内部复制一个第二真值。

`Pagination` 必需字段：`cursor`（本页实际规范起点，第一页为`v1:0`）、`next_cursor`（非终页为下一页规范cursor字符串，终页为JSON null且字段不省略）、`page_size`、`returned`、`truncated`。终页null明确表示没有下一页，与§3.2(9)和P04类型一致，不属于无意义null；它是nullable的required字段，不是optional。所有计数为非负整数；`page_size`范围1～250；不适用分页的操作完全省略`pagination`。本处勘误依据`../2026.09.20/2026.09.20-13-PC018终页字段勘误与自评续作.md`，修正后身份由`current-normative-inputs-pc019-r02.json`固定，旧输入manifest只保留修正前身份；完整自评未完成，实施门仍关闭。

### 4.2 TargetContext

公共类接受可注入的 `list_windows_clients()` 与 endpoint operation，生产实现调用当前 gRPC/VQL底座。公开方法：

- `get_client_id()`：缓存命中零查询；未命中查询全部Windows候选并严格检查基数；只返回真实client_id。
- `run_with_client(operation)`：取得缓存并执行；operation失败后由生产适配器按第3.2节第5项核验client_id存在性，只有专用`CachedClientIdNotFound`才清缓存、重新解析和重试一次；第二次同错转为`CLIENT_ID_NOT_FOUND`，不再重试。
- `clear()`：只供MCP进程生命周期和测试清理，不注册为工具。

缓存对象由 bridge 进程创建一次；进程结束自然丢弃。测试fixture必须证明两个MCP进程各自首次查询，不能使用磁盘或跨进程缓存。

### 4.3 输出限制与共享后端原语

- `paginate_result(base_result, rows, cursor, page_size)`实施第3.2节第8～9项，`base_result`包含operation/status/适用ID/warnings并由helper构造最终DataResult；保持输入顺序、不漏不重。
- `limit_unpaged_result(base_result, rows)`最多返回250行且对最终DataResult应用245554-byte上限；超限成功返回已容纳前缀并明确`truncated=true`，单行超限为`ROW_TOO_LARGE`。
- cursor边界表：空源与offset0返回0行终页；offset==len返回0行终页；0<offset<len从该行继续；offset>len为`INVALID_ARGUMENT`。源在调用间增长时原offset仍指向原顺序位置；源缩短导致offset>len时失败，P04不得自动归零。合法cursor在每个请求明确选择且通过验证的Flow/source内独立解释；不存在的Flow仍按对象层NOT_FOUND，非法source和超出该源范围的offset仍为INVALID_ARGUMENT。不能只因相同offset曾在另一个合法上下文使用就拒绝本次请求；不承诺流式变化中的跨页结果为后端原子快照。
- `VelociraptorBackend` 是薄适配边界：配置/连接与 `run_vql_query` 保留现有可复用核心；提供严格Windows client枚举、普通collection启动、Flow详情/结果源读取所需最小方法。P02不实现P04五个固定Flow工具，也不定义Hunt/file/triage产品行为。
- collection启动先取得真实`flow_id`，随后立即用该client_id/flow_id只读回读Flow详情并返回其真实state；创建响应缺flow_id或回读缺真实state均为`BACKEND_ERROR`，不得合成ID或`SUBMITTED`状态。P01实测状态值`FINISHED`直接保留；其他后端字符串同样原样保留，不由P02枚举改写。

### 4.4 错误决策表

| code | owning layer / 精确触发 | retryable | details白名单与排他关系 |
| --- | --- | --- | --- |
| `CONFIG_NOT_FOUND` | 配置层；显式/解析后的API config不存在或不可读 | false | `source`仅为`environment/default`，不含实际路径；不用于YAML内容错误 |
| `AUTHENTICATION_FAILED` | gRPC层；`UNAUTHENTICATED`或`PERMISSION_DENIED` | false | `grpc_status`；与连接失败排他 |
| `CONNECTION_FAILED` | gRPC层；`UNAVAILABLE`或TLS握手/连接建立失败 | true | `grpc_status`；不含连接串/证书 |
| `BACKEND_TIMEOUT` | gRPC层；`DEADLINE_EXCEEDED` | true | `operation`、`timeout_seconds`；不触发client换目标 |
| `CLIENT_NOT_FOUND` | TargetContext首次/重解析时Windows候选恰为0 | true | `candidate_count=0` |
| `CLIENT_NOT_UNIQUE` | TargetContext候选大于1 | false | `candidate_count`；不含主机名/IP |
| `CLIENT_ID_NOT_FOUND` | 已命中专用失效谓词并完成一次重解析/重试后仍不存在 | true | `retries=1`；不与首次0候选混用 |
| `INVALID_ARGUMENT` | 公共校验层拒绝类型、page_size、cursor或参数 | false | `field`、`reason`、允许边界；不回显完整输入 |
| `NOT_FOUND` | P04对象层；明确Flow/Hunt/file存在性查询成功且0项 | false | `object_type`、脱敏ID；不用于连接/权限失败 |
| `NOT_CANCELLABLE` | P04 Flow层；真实终态或后端明确拒绝取消 | false | `object_type=flow`、真实`state`；不伪造成取消成功 |
| `ROW_TOO_LARGE` | 输出层；一行连同最终包络超过245554 bytes | false | `actual_bytes`、`limit_bytes`、`row_index` |
| `BACKEND_ERROR` | 后端返回错误、非法JSON、缺真实ID/state或未单列的明确gRPC状态 | false | `operation`、可公开`grpc_status`或`reason`；原异常文本不透传 |
| `INTERNAL_ERROR` | 公共层未预期异常的最后兜底 | false | 只含`exception_type`和`correlation_id`；message固定通用文本 |

生产映射必须按表从上到下应用；未知异常只能进入`INTERNAL_ERROR`。P04拥有的`NOT_FOUND/NOT_CANCELLABLE`在P02只冻结模型、排他关系和受控适配器测试，真实生命周期触发由P04验收。所有message为面向使用者的动作/影响说明；details以白名单重建，禁止直接使用`str(exc)`。
