## 6. 每次失败怎么处理

| 发现 | 正确处理 | 禁止的捷径 |
| --- | --- | --- |
| Python/PowerShell/封包实现错误 | 保留原错误，最小修复，新 UUID Windows 回归 | 改 exit 或吞异常 |
| Windows MCP HTTP 200 但命令失败 | 解析真实工具返回和进程 exit，记失败 | 只看 HTTP 状态宣布完成 |
| 缺测试文件/导入依赖 | 补冻结闭包，重新传输测试 | 删除该测试 |
| 完整原件缺失/语义 parser 未实施 | 补真实采集和解析；相应门保持关闭 | 把 summary 改名为 raw |
| 仅源外旧问题未恶化 | 保存环境观察与基线/diff归因 | 无证据归罪本轮或隐藏 |
| 无法归因且无等价证据 | 只阻断受影响条目，列最小证据缺口 | 扩张为全部失败或默认通过 |
| VM/MAC/IP/快照不匹配 | 停该目标操作，报告对象证据 | 切 .149 或改 DHCP |
| token/API 配置缺失 | 只报告来源类别缺失 | 生成 token/回显 secret |
| 188 已存在/候选内容需变 | P05 候选代次重新裁决 | 覆盖、删除或拼旧周期 |
| 网络观察面不够/来源版本漂移 | 有证据的 PLAN-CHANGE 候选 | 放宽来源、白名单或完整性门 |
| 旧 CHK 尚无新独立证据 | 保持 open/blocked，提交修复证据 | 作者直接写 closed |

每轮记录最小字段：阶段/目标、规范与源码身份、run/restore/VM/service/session 身份、实际命令与 UTC/exit、预期断言、实际结果、原件路径/size/SHA、失败归因、资源所有权与清理、仍未通过项、下一最小动作。只记录执行事实；计划执行、文件存在、工具调用成功、单测通过和正式验收通过是五种不同状态。
