### 0.1 精确状态、引用和包

唯一入口是canonical原字节SHA-256 `2d5f378d20c163401b1c4ce7087db102a4719b394fc7a9408baa7d63d7ca4385`的schema5/epoch6/`NETWORK_ACTIVE`/188；仅准许一次PC020 migration，普通selector拒绝旧188，漂移返回主方。新状态为schema6 epoch7/`PREPARATION_BASELINE`/187和schema6 epoch8/`NETWORK_ACTIVE`/189。189全名固定`Snapshot 189-Velociraptor-MCP可恢复验收基线`，必须现场零匹配→一次创建→恰一匹配→实读marker；187/188保留，不覆盖、改名、删除或自动选190。

canonical exact root keys为：

`schema_version/workflow_id/epoch/phase/active_snapshot/automatic_restore_allowlist/retired_snapshots/migration_evidence/preparation_evidence/activation_evidence`

migration Ref exact keys为`kind/source/evidence_path/evidence_sha256/predecessor_sha256/migrated_at`，kind=`pc020-requalification-migration-v1`、source=`pc020-migration`；preparation Ref exact keys为`kind/source/evidence_path/evidence_sha256/qualified_at`，kind=`pc020-snapshot187-preparation-v1`、source=`pc020-preparation-admission`；activation Ref仍为`source/evidence_path/evidence_sha256/activated_at`，source=`snapshot189-activation`，根kind=`snapshot189-activation-evidence-v1`。目录分别是P05固定证据根下`pc020-migration/<uuid>/`、`pc020-preparation/<uuid>/`、`activation-189/<uuid>/`。 新189 activation根exact keys增加required `issued_at`；它是cycle2完成验证后、epoch8 `.next`前实际签发时的合法UTC RFC3339 Z字符串并受根SHA覆盖。canonical `activated_at`与root `issued_at`逐字相等；缺失、null、非法、不等或从mtime/当前时钟/receipt补值均拒绝。

设active名`a`、allowlist集合`L`、retired集合`R`：`L={a}`、`L∩R=∅`、retired唯一。active在allowlist中，不要求二者互斥。epoch7从前驱retired按原序移除187后追加188，得到183/184/Snapshot1/186/188；epoch8再追加187。所有Ref时间只表示不可变证据签发时间，不冒充canonical提交时间；尤其activation `issued_at`不等于未来replace完成时间，且不引入跨机时钟比较或额外精度。

每份package manifest固定管辖树`T`和排除集`E`；members恰为`T`的全部普通文件减`E`，每路径一次且身份相等。`E`只含manifest自身及在`T`同层直接引用它的根record；外层必须覆盖所有嵌套manifest/root，不允许任意排除、自hash、链接/reparse、逃逸、缺件或冲突重复。

### 0.2 因果顺序与稳定依赖边

恢复前preparation admission只含当前187唯一名称/marker/VM身份、非秘密证据保全和retired准备例外，不含revert、恢复后ready、Flow、报告或Triage/file。因果顺序固定为：冻结规范/产品source→原始tree/metadata/VM观察与保全→preparation package/admission→递归复制历史旧canonical/baseline/activation和preparation→migration package/record→原子epoch7→一次实际187恢复→部署/依赖/fixture→ready/security/resource+initial正式报告/Triage/file→189零到一创建→candidate cycle1完整返回→cycle2完整返回并验证→以required `issued_at`签发activation graph→校验canonical `activated_at`逐字等值→原子epoch8→P06→P07。任何后置事实不得回填前置准入，activation不得引用epoch8或其transition receipt。

三个Phase可共享规范/产品源码、冻结preparation/migration包；两个candidate cycle可共享单一189创建记录，initial不得消费未来创建。每Phase的restore_attempt_id、run_id、Flow、raw、ready、network/service、report、session/process、Triage/file和Phase manifest独立语义绑定。hash或路径相同本身不是串场判据；把同一运行事实冒充第二轮仍失败。

稳定依赖边保持：`OUT-014/020/023/053/054 → P05 IMP/ACC → OUT-021/022与P06 → P07 ACC-024/025`；REQ-026仍映射OUT-053/ACC-026，OUT-026仍属CON-001。PC020不新增Pxx、产品接口、权限或fallback。

`PC017-FILE-VIEW/IDENTITY/READ`显式细化REQ-009/010、RACC-009/010及累计34/36/37：`list_flow_files`列出Flow实际采集的全部逻辑原文件；顶层`Type=idx`的稀疏范围表是对应原文件的内部重建元数据，不是独立可选下载对象。普通天然`.idx`仍是原文件，禁止按后缀过滤。清单schema不变，只读uploads metadata、不读取内容且不落盘；成功warnings稳定增加`sparse_indexes_internal:<去重配对数>`。服务器范围表原件保持不删不改。`file_size`为逻辑长度，`uploaded_size`为data对象非洞存储字节数，idx镜像大小不重复计入。

完整uploads先分类：Type缺失/空为data，精确`idx`为辅助索引，未知或非字符串Type拒绝；嵌套Type非空时须与顶层一致。data `file_id`继续由原`accessor/components/upload_id` identity的canonical JSON SHA-256产生，client/flow components作用域必须成立，UploadId=0不冒充上传序号；完全同一行稳定去重，冲突fail-closed。idx须以相同Components/Accessor/UploadId和data展示路径加`.idx`与唯一data配对，重复同一idx可去重，孤儿、异元数据、多义配对或`file_size!=uploaded_size`却无idx均拒绝。所有大小必须是非负非bool整数且`uploaded_size<=file_size`。隐藏idx前须检查派生selector与全部data/idx selector无歧义，包含天然`.idx`和当前Windows filestore下大小写等价别名；碰撞拒绝整个清单/下载。

下载先重新枚举并完成全部验证，再按精确data file_id选择。普通文件显式`Padding=false`并要求逻辑/非洞长度相等。稀疏文件先`Padding=false`以每块不超过1 MiB读到0字节EOF、实计紧凑长度等于`uploaded_size`，该预读不落盘不返回内容；再`Padding=true`重建到唯一`.part`，0字节EOF，实计逻辑长度等于`file_size`并对全部逻辑字节（含零洞）计算SHA-256。原子发布前再次枚举，data与idx配对、selector、大小和路径均不得漂移；此复核不冒称后端原子快照、源内容未变或端到端取证签名。ERROR Flow的完整单文件可以下载但不能改判Flow或triage成功。截短、缺失、元数据矛盾、实际长度不符与发布前后端错误不得由本请求创建新完成文件；`os.link`提交后的复核或part清理故障则按OUT-010/037返回过滤错误并保留完成目标。既有安全根、reparse/逃逸拒绝、`xb`唯一`.part`、fsync、`os.link`不覆盖、ALREADY_EXISTS、只尝试安全清理本次owned part和响应无二进制全部保持；清理失败或所有权不可信时允许part残留。辅助idx ID作为未知file_id拒绝，不fallback到data。

采纳理由是向调用方交付可直接分析的逻辑原文件；idx metadata镜像大小并非真实索引长度，伪造大小或只补Type不能兑现精确读取。代价是接口不提供原始紧凑副本或独立范围表导出，稀疏下载增加一次紧凑预读的时间/网络成本。若未来需要保全存储层对象/底层格式，或依赖端版本、Type/Components、selector编码、Padding、大小口径改变使稳定配对/重建不可证，停止受影响条目并重新裁决导出接口，不猜文件名、不接受未知Type fallback、不用hash唯一性替代selector可读性。

当前真实分诊仍未通过；本文件实现与完整自评也未通过。PC016历史原件搜索继续暂停，P05激活门和实施后独立核验保持，旧历史1 GiB失败与既有hash不被改写。

## 5. 关键数据流、状态和结束条件

### 5.1 启动与工具清单

启动配置提供Velociraptor连接信息、下载根目录、传输模式，以及正式模式所需的准确host-only监听地址、固定端口28790、固定路径`/mcp`、部署者提供的Bearer token、允许Host和宿主机防火墙来源。空token、通配监听、非28790端口或非`/mcp`路径均使正式启动失败。server先连接root Org，读取实际artifact metadata，对正式allowlist逐项验证存在性、CLIENT类型、名称冲突和可映射schema，再连同12个固定工具完成全量schema校验。只有全部通过才一次性进入ready并服务tools/list；失败则stderr或服务日志输出明确原因、非零退出且不提供残缺入口。

正式调用链固定为“虚拟机外客户端→host-only网络→VM内`28790/mcp`→共享MCP工具注册/业务实现→VM内Velociraptor gRPC `127.0.0.1:8001`”。正式适配器保持单进程和有状态Streamable HTTP会话，校验Bearer和Host并开启DNS rebinding防护。官方非浏览器SDK可以不发送Origin；请求一旦携带Origin，只允许部署配置显式列出的值，未允许值拒绝。stdio适配器只允许测试入口使用同一注册实例，不得成为跨VM代理；Win10VM MCP不参与正式数据流。

每次HTTP进程启动生成一个非秘密随机`server_instance_id`，所有通过请求门的MCP响应以`X-MCP-Server-Instance`返回；同进程值不变，重启必须变化，客户端同名请求头不能覆盖。MCP会话身份只取SDK真实响应中的`Mcp-Session-Id`，不得用客户端自报字段替代。

client解析不属于启动前置：第一次 endpoint 调用时解析唯一 Windows client并缓存。恰有一个候选时才能继续；零个候选返回未找到错误，多个候选返回目标不唯一错误，二者都不得猜测或选取目标。MCP进程结束即丢弃缓存；重启重新解析。server明确返回缓存 ID 不存在时，才允许一次清缓存、重解析和单次重试；离线、超时和 collection失败保持原目标并返回真实错误。

### 5.2 动态 artifact 调用

调用方选择以准确 artifact 原名注册的工具并只提交业务参数。MCP只编码显式提供的参数，省略项由 Velociraptor默认值处理。目标上下文注入 root Org和唯一client，启动一次普通 collection，返回 operation、真实 flow_id、真实初始 status及必要 warnings。后续状态、结果和文件全部转由固定 Flow工具处理。

动态输入 schema 必须保留原参数名、说明、选项和校验提示；bool/int/float/choices/multichoice映射为对应JSON类型，文本、正则、YARA、时间、CSV采用可验证格式。hidden、upload/upload_file和三个YARA artifact的YaraUrl不暴露；YaraRule为文本。未知类型阻断启动，不降级为自由字符串。

### 5.3 Flow 生命周期

- get_flow_status(flow_id)：读取真实状态，不取结果、不下载文件。
- get_flow_results(flow_id, source?, cursor?, page_size?)：按 source和稳定分页位置返回有限数据与pagination。
- list_flow_files(flow_id)：只枚举文件及稳定 file_id，不落盘。
- download_flow_file(flow_id, file_id)：下载一个明确文件到配置根目录内，以Flow和文件唯一标识组织，流式写临时文件并计算SHA-256，完成后原子成为完整文件；返回路径、大小、哈希、原始路径和flow_id。
- cancel_flow(flow_id)：只取消明确指定且后端仍可取消的Flow；终态或未知ID返回稳定真实错误。

Flow状态和结果源枚举以P01证据为准。进行中不是成功完成也不是错误；正常完成但没有数据可作为明确空结果。

### 5.4 Hunt 生命周期

- start_hunt(artifact, parameters?, description?)只接受正式动态allowlist中的artifact和同一结构化参数，固定root Org，创建Hunt后只加入内部唯一client，返回真实hunt_id。
- get_hunt_status(hunt_id)返回真实Hunt状态和唯一主要flow_id；结果经Flow工具取得。
- stop_hunt(hunt_id)只阻止后续调度，不隐式取消已经运行的Flow；若要取消该Flow，调用方必须显式调用cancel_flow。

第二个 endpoint、子 Org、多主机 Hunt、多个主要Flow或实际后端无法提供要求的关联关系，均触发REQ-003/REQ-011的局部重新裁决，不得在实现中暗增多目标模型。

### 5.5 文件采集、VQL、triage和结束进程

- collect_file(path)接受明确Windows路径或Velociraptor支持的通配符，立即返回真实Flow；文件仍须 list_flow_files 后按file_id逐个下载。
- run_vql(query)固定root Org且无危险开关；在P01锁定、P02固化的行数和字节数上限内返回数据，超限明确truncated。
- collect_forensic_triage()无参数，只调用锁定并验证的 Windows.Triage.Targets _BasicCollection；立即返回真实Flow，结果和文件复用Flow链路。
- kill_process(pid)固定唯一client和root Org，启动 Generic.Utils.KillProcess并返回真实Flow和初始状态。

### 5.6 结构化结果

成功结果至少按语义提供 operation、status，以及适用的flow_id、hunt_id、data、pagination、warnings。字段不适用时不得伪造值。失败是MCP原生错误结果，isError=true，并提供稳定code、可理解message、retryable和details。不得同时复制一份JSON字符串作为兼容输出。

### 5.7 测试数据与情景
