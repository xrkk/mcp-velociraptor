采用现有HTTP x-velo-transfer-id/request-digest/offset/direction；pull额外count-per-chunk/chunk-count。名称均加x-velo-前缀且各恰一值；重复（包括大小写变体）、逗号合并、前后空白、非规范十进制拒绝。pull请求为完整VBT1帧、header恰{}、payload零字节，范围只取HTTP headers。push header恰chunks数组，各项count/chunk_sha256，禁止pull参数。不得同时从frame与headers取同一逻辑参数。Content-Type固定application/octet-stream。所有HTTP元数据仍需请求身份/方向/摘要联合校验，header长度预算不代替MCP session检查。响应形状采用T011候选，按方向选组件而非用任意oneOf猜方向；严格耗尽payload。

## OD02 capability协商

## OD05 双端发布身份

保留候选receipt schema1/kind pc026-dual-publication-receipt-v1、19顶键及四UTC时间，不能靠时间字符串证明持久化。新增每member的host_identity/guest_identity均按不同平台精确结构验证，不再把host UID塞入SID字段。

host_identity exact：platform="posix"、device为规范无符号十进制字符串、inode同格式、owner_uid同格式、owner_gid同格式、principal_uid同格式、mode为四位八进制权限串（不含类型位）、acl_sha256为64小写hex。摘要对应完整保存的规范化ACL证据：至少mode/owner/group，若有扩展ACL必须完整排序编码，不支持读取时拒绝，不能只把mode假称完整ACL。

guest_identity exact：platform="windows"、volume_serial为16位小写hex、file_id为32位小写hex（FileIdInfo原16字节按返回内存顺序hex，不作GUID转换）、owner_sid/principal_sid为规范Windows SID字符串、acl_sha256为64小写hex。ACL摘要取同句柄身份绑定的原始self-relative security descriptor字节，其归档Ref必须能定位；不以友好账户名或临时PowerShell身份替代服务/controller实际principal。

上述ACL原件和身份观察记录放在部署/发布证据中；receipt新增顶键identity_evidence，类型为唯一归档manifest的path/size/sha256 Ref，故最终顶键总数20。identity_evidence内逐member/endpoint唯一映射原件Ref和观察身份，完整覆盖，缺失/多余/重复拒绝。root_mapping摘要固定UTF8 JSON ensure_ascii=false/sort_keys=true/separators=(',',':')、无换行、无非有限数。成员按relative_path UTF8字节排序，不能用不稳定对象遍历序。跨端volume/file值无需相同，路径/size/content hash须相同；主机模式值不替代Windows ACL校验。

## OD06 未知push结果的重验完成证明

status先观察同ID/digest/channel/package，但普通verified_offset值不等于新重验。未知push结果（包括binary/JSON超时或坏响应）禁止直接重发；固定原request再次begin，沿现有verify_partial worker执行有界完整prefix验证，不续期原deadline。若仍有活writer则等待同一任务结束并在剩余deadline内重验，不能争抢新writer。

State增加必需prefix_verification，值null或exact对象：schema="velo.transfer.prefix-verification.v1"、request_digest=64hex、worker_nonce非空string、verified_offset非负整数、chunk_count非负整数、ledger_sha256=64hex、completed=true。该对象必须在对应verify_partial worker完整读取实际payload/ledger、核identity/预算/连续hash并持久化成功后，和state同一受保护修订原子保存；使用该worker nonce，不因进程退出或stopped=true自动补造。ledger摘要是截至verified_offset的完整持久ledger原字节；零前缀使用空字节SHA但仍验证owned初态。合法写入一旦开始、offset/ledger/身份变动、重验开始或失败、任务取消时清空该证明。不可将旧成功证明留给新offset使用。

客户端先记录status旧nonce/证明，再begin resume，必须看到对应新verify_partial nonce完成、error=null、worker已停止且lease释放、证明digest/offset/chunk_count/ledger与该重验state一致，才按此offset续传；即使begin响应丢失，也只能接受相对于事前观察的新nonce完整证明。无法区分新旧worker则chunk_outcome_unresolved，不盲重试begin或batch。仅依赖stopped与error为空不足，因为worker可能在证明保存前崩溃。完成全部字节也必须重验后转原finish流程。

追加正反矩阵：重验前/中/保存前崩溃无证明；成功保存且返回丢失可恢复；旧nonce/错digest/旧offset/被篡改ledger拒绝；合法下一chunk使证明失效；零前缀、deadline不续期、foreign尾巴不截断、活writer不并发。此新增output/持久字段属于PC026契约变化，必须同步schemas/消费者/存储验证器和源freeze，不能宣称现代码已实现。

### 3.2 P03冻结决定

1. allowlist以产品源码中的准确118项`name -> approved_definition_sha256`映射承接需求附录A与P01批准身份；启动时对root Org实时metadata双向核对这118项，不从“所有Windows CLIENT”自动扩张。哈希算法严格为`sha256(raw_definition.encode("utf-8")).hexdigest()`：`raw_definition`是root API JSON解码后未经strip、换行转换、Unicode规范化或重序列化的`raw`字符串。任一同名定义哈希不同都在handler注册前按FB-P03-003原子失败并列出名称和expected/actual hash，不输出raw正文。
2. 每个artifact生成一个独立handler，但不手写118套函数。生成器为每个参数建立安全内部名`p0..pN`与准确外部alias，并注入`inspect.Signature`；MCP SDK按alias生成schema和回传参数。Win10VM Spike已证明含空格的`Boot execute`及数组`Tables`可注册、调用并得到结构化结果。
3. 所有字段在JSON Schema中都不是`required`。Python签名使用“非nullable注解 + default None”：调用省略时生成器丢弃None，显式null由SDK校验拒绝，从而只向Velociraptor发送调用方明确提供且非null的值。不得将backend default复制进请求。
4. 类型表固定为：空类型/`string`/`regex`/`yara`/`timestamp`/`csv`映射JSON string；`bool`映射boolean；`int`/`int64`映射integer；`float`映射number；`choices`映射单值enum string；`multichoice`映射enum string array。schema以`x-velociraptor-type`、`x-velociraptor-default`保留真实类型和后端默认，以`format`标注regex/yara/timestamp/csv；`description`、`friendly_name`、`choices`、`validating_regex`原样承接。`validating_regex`非空时先验证其自身可编译，再作为字符串`pattern`；坏表达式使启动原子失败。
5. `hidden`、`upload`、`upload_file`一律不进入schema；三个YARA artifact中的`YaraUrl`按名称再做独立拒绝断言，即使未来metadata类型漂移也不能暴露。`YaraRule`保持string并标注yara格式。未知类型、空/重复参数名、空/重复artifact名、类型非CLIENT、缺失允许项、工具名冲突或任一输入/输出schema非法均使进程在`mcp.run()`前失败。
6. 失败启动通过统一`main()`边界把一句不含秘密的诊断写stderr并返回非零；不得写stdout、不得进入部分服务。正常启动完成全部118项注册后才调用`mcp.run()`，该进程的清单不再改变；metadata变化只在重启时重新读取。
7. 动态调用复用唯一`TargetContext.run_with_client`和`VelociraptorBackend.start_collection`；`operation`使用不与已退出旧工具混淆的`start_artifact_collection`，warnings只承载可公开依赖提示，`flow_id/status`来自后端。handler不轮询终态、不取结果、不建Hunt。
8. P03分两步取消旧注册：先使动态118项及其针对性测试通过，再取消35个旧`windows_*`、两个旧YARA、`collect_artifact`、`hunt_across_fleet`和三个`list_*_artifacts` decorator并重跑；同时为Windows-only门禁取消15个Linux和10个macOS helper注册。函数源码仍保留；P04负责其余固定/collection/result迁移，P07才按无引用证据物理删除旧Windows/YARA实现。
9. 真实118项中17个Autoruns参数名包含空格。backend参数键只能来自已验证spec；普通标识符原样编码，含空格的已批准键用VQL反引号引用。metadata键含反引号、控制字符或空值时原子失败。Win10VM root Org Spike已证明`dict(`Boot execute`=FALSE)`得到准确键；不得放宽成调用方可提交任意VQL标识符。

## 4. 动态注册与数据契约

### 4.1 metadata快照

`read_root_artifact_definitions()`在root Org执行一次只读查询，返回每个定义的`name/type/description/parameters/raw`。每个参数只接受`name/type/default/description/friendly_name/choices/validating_regex`这组已证字段；多余metadata不进入外部schema。注册器先按第3.2节第1项对未经变换的raw字符串计算SHA-256并与源码批准映射逐项比较，再把真实定义规范化为不可变spec；当前哈希和完整矩阵摘要只进入脱敏测试证据，不在产品响应中回传原始定义。

启动双向比较的批准集合始终是源码118项name/hash映射；实际root Org可以有其他定义，但它们不注册。批准集合中缺失、重复、非CLIENT或同名raw hash不符都是失败；附录B、CLIENT_EVENT、其他CLIENT和自定义项没有通用旁路。P04的`start_hunt`必须复用本模块同一allowlist/spec，而不能复制第二份。

### 4.2 输入schema和编码

每个工具名严格等于artifact原名；description严格取实际metadata说明。输入properties严格等于“实际参数减hidden/upload/upload_file，再减三个YaraUrl”；properties名称保持原大小写和空格。字段全部可省略，`additionalProperties=false`。注册后把SDK生成的参数模型设为`extra=forbid`并强制重建，再发布同一模型生成的schema；Win10VM Spike已证明extra字段在handler前失败。choice/multichoice必须拒绝集合外值；bool/int/int64/float必须拒绝字符串冒充，且bool不得被integer接受；显式null和未声明字段由SDK拒绝。生成器在进入backend前再次按spec把值归一化，regex和非空`validating_regex`失败返回`INVALID_ARGUMENT`。

后端调用字典由接收到的alias中值不为None的条目构造；空字典传为`None`。不读取或填入`x-velociraptor-default`。三个YaraRule是普通文本；任何URL、文件上传、临时服务或清理生命周期都不存在。

### 4.3 原子启动与结构化输出

注册过程在stdio服务前依次执行：初始化API连接；读取metadata；验证集合/类型/参数；对全部118项构建handler；在隔离的候选server中检查工具名冲突、输入schema和`FlowReferenceResult`输出schema；全部成功后形成正式固定server并运行。实现可以在同一尚未运行的server上先构建后提交注册，但必须证明任何异常时从未进入stdio read loop，不能捕获错误后继续提供残缺清单。

动态成功结果唯一为`FlowReferenceResult(operation="start_artifact_collection", status=<真实初始state>, warnings=<零或公开依赖提示>, flow_id=<真实ID>)`。异常经P02 `error_result`转换；用户输入错误为`INVALID_ARGUMENT`，配置/连接/目标/后端错误沿P02稳定码。进程启动期错误不是工具调用结果，必须是非零退出和stderr诊断。
