## 采纳时固定的接口细节

- DELETE 成功响应必须各有且仅有一个 `X-Velo-Observation-Close` 和 `X-Velo-Observation-Cut` header，前者精确为 `pc026-session-close-v1`。后者为 cut 三键 Ref 的 canonical UTF-8 JSON（含单 LF）的无 padding base64url，编码长度最多 2048 ASCII bytes；拒重复、合并值、非 canonical 编码、额外字段及越界值。无成功屏障不得发送这两个成功 header。
- 该 wire descriptor 的 path 相对批准 namespace，精确指向 `e<instance>/s<SHA256(session UTF8)>/cut.json`。header 只作关联，不授权来源。host 下载原 session cut 后将 wire descriptor 与实际源坐标、字节长度和 SHA 对照，再产生 host run base 下的 Ref。maintenance.close.cut_ref 保存自身 wire descriptor，故它的 base 是批准 namespace，不是 host run base；maintenance.original_cut_ref 及实际已取得的原件 Ref 仍相对 host run base。不下载维护 session 自身 cut，不宣称其跨端内容已核验。
- 完整路径及 pending 名的 UTF-16 长度限制必须在写入前按实际批准 root 核验；现有 Q 盘路径不是新 export 布局合格证明。必要时后续选择更短的新批准 root，不能放宽 `<248` 门槛或改旧原件路径。
- SDK pin 是实际目标部署的精确版本与源指纹。当前 host 与历史 guest 的 Python/httpx2 版本不同；host 验证不自动证明 guest pin 合格，部署阶段必须显式解决版本一致性或重新核验目标 pin，不能跳过 drift gate。
- B1 可用仅测试内部构造的 MODEL exporter 验证真实 SDK/HTTP 生命周期；其 cut 必须真验证完整前缀并发布读回，不能假函数返回成功。生产 native exporter/批准输入未齐时正式 HTTP 启动拒绝，不能增加 env/CLI 绕过开关。原 stdio 行为保留。

## L2 有限状态与线性化

instance状态 STARTING→ACTIVE→DRAINING→CLOSED；任意未知→UNKNOWN且禁止新动作；UNKNOWN不恢复ACTIVE或变CLOSED，可继续保全已受理work的安全尾部和恰一次释放。DRAINING停止新session/new tools/new binary，允许已有票据收束；不借关闭预留写新BEGIN。session OPEN→CLOSING→CLOSED，任意未知→UNKNOWN；初始化尚未完成用内部pending creation lease，不称OPEN。CLOSED只表示该session范围已知闭合，可有FAILED/REJECTED业务；成功资格另验。

同一controller短state锁原子排序“认领入口票据/预算”和“转CLOSING/DRAINING”。先登记者归关闭集合，后到者403/409/503有限拒绝（认证401，错session404，closed/closing409，draining/耗尽503），不得向已cut的session追加BEGIN。DELETE不是业务tool occurrence；既有owner/session验证通过才改变状态。每个受理的HTTP envelope、SDK request/notification、GET/SSE连接及chunkbin有独立有限work lease，queued到真正结束都占位。仅async middleware finally登记太晚，HTTP202也不证明notification处理结束。创建manager session前登记pending lease，实际runner启动/initialize响应绑定后才OPEN；创建失败同样必须结清该lease或UNKNOWN。

锁次序：state锁仅短修改；catalog串行交易锁独立；不持state/catalog锁等待SDK、thread或native I/O。不反向从journal锁取catalog锁。ledger组/config/root受控reader存活到全instance close，出口不能重复关闭借用group。

## L3 eligible occurrence、永久duplicate及SDK队列

原observer中duplicate/max_requests在journal_factory之前；仅安装ledger工厂会漏duplicate BEGIN，必须改**私有受理ticket seam**。外层依次认证、Host/Origin、body大小/完整JSON唯一键/有限Unicode、protocol/session/owner、observer等价eligible形状（typed id严格int非bool或string、非空tool、dict arguments，默认{}）及canonical编码，再在L2锁内登记。有效格式且在OPEN额度内的每次tools/call立即ledger.begin，含duplicate/active/seen/bytes拒绝。NEW→ledger.accept→持久ACK已知之后才可enqueue SDK/business；REJECTED已有BEGIN+END，直接有限JSON-RPC错误返回、不发SDK、不造第二scope/accept。begin/accept未知零业务，sticky instance UNKNOWN；A额度耗尽后的新请求不造BEGIN，转DRAINING并独立raw分类。

ticket包含attempt lease及已受理journal。正式observer只认私有票据并唯一claim，不再抢先以旧scopes门挡掉已BEGIN occurrence；旧factory=None路径仍按现行为。NEW永久seen，不因failed/cancel/关闭释放。SDK tool schema/name拒绝发生在ACK后也必须通过实际scope的raised seal/close→END，零业务但不可伪称门前拒。若请求在enqueue前断线、或队列在handler之前被取消，controller在确认从未进入任何worker后唯一claim已受理journal，seal(cancelled)/close/finish；不能把未claim journal遗弃，也不能在可能worker运行时抢claim。无法确认handoff所有权则UNKNOWN。

实际SDK dispatcher对同coerced id覆盖_in_flight，transport request slots取str(id)。因此所有JSON-RPC request（含initialize/tools/list/unknown method）在同session按**str(id) wire slot**串行发送至SDK；int7/string7仍两个typed父键/独立attempt，不能合并为duplicate。后者有限排队，等前者SDK response stream真正清理且handler已结束后enqueue；断线不释放slot。取消notification按actual typed/coerced目标分配给现活动slot，队列取消由内部票据定位并有原raw依据。对相同非tool id也拒并发slot覆盖或串行，不能仅保护tools/call。slot数/queue受配置，无法排队的NEW在零worker证据后cancelled收束；新拒绝不超越ledger预算。

所有notification与非toolrequest参与SDK runner barrier，但不伪造tools/call父键/08 event。未知method返回SDK真实error仍是登记的工作。非法JSON/invalid typed父键/无session/外层安全拒/格式无法编码在BEGIN前，raw分类不得假序号；未知/截断raw不可证明任何请求安全拒绝。

## L4 真正worker、取消和主错

真实栈：bridge→MCPServer/lowlevel→StreamableHTTPSessionManager._handle_stateful_request→transport.connect→runner.serve_loop→JSONRPCDispatcher.run/_handle_request→runner._on_request middleware→tool_manager.call_tool→FuncMetadata.call_fn。普通同步tools使用anyio.to_thread.run_sync，已安装默认abandon_on_cancel=False，取消await仍等原线程返回；dispatcher peer_cancel_mode默认interrupt且可能wire抑制。COMPLETE/returned不代表客户端收到成功。

每个内部SDK lease需从enqueue持有至handler/notification任务及发送清理结束；最终整个dispatcher taskgroup join、connection/transport cleanup结束的runner退出才释放session最终lease。不能以session map消失、_terminated、HTTP response、_in_flight大小或scope snapshot sealed推断所有work结束。工具不得脱离受控任务组派生后台；若未来工具有此需求先扩真实登记协议。

/chunkbin现使用asyncio.to_thread，取消await不停止native线程。必须在endpoint进入线程前独立binary ticket，保留controller拥有的Task/Future，await采用shield；native wrapper最外层finally设置真实线程退出信号（连异常都记录），只有future完成且信号已见才能登记退出及释放。HTTP任务取消只标客户端断线，不能销毁最后future引用；operation/transfer资源由实际线程使用期间保留，收束仍纳入session close。binary key为独立operation sequence+真实session+instance及raw request body SHA，不借tools/call id、不给08假父键或业务event。无法证明退出不发布close成功，不kill线程。

实际awaited worker退出→scope._finish实际outcome→journal seal/close→ledger.finish实际复读END→释放attempt work。scope观察失败可把snapshot outcome改raised，但journal原seal可能returned/FAILED；finish必须取实际seal原outcome，不能用变更snapshot给ledger造不一致。primary异常/取消同对象保留；清理失败有限add_note并记录阶段，不覆盖primary。无primary则清理错传播；handle每个最多一次实际close，未知不重试/自动修复/删除。批准漂移禁止不安全尾写，但不以漂移为由抢关仍被活worker使用的资源。

## L5 DELETE、drain和关闭谓词

授权DELETE：L2原子CLOSING并关闭新enqueue→strict terminate唤醒SDK流→await所有已登记SDK/queued/binary true exits（含未claim票据明确收束）→全部NEW journal关闭且END已知/REJECTED已END→SDK runner/taskgroup/connection/transport cleanup已知退出→C候选安全global prefix+session投影验证→publish cut/export并实际readback、reader/writer/临时leaf关闭确认→CLOSED→才发送HTTP200。即使其他session OPEN也允许该session关闭，不等INSTANCE_END、不关闭instance root。原SDK DELETE的200必须拦住，不能先透传再后台补cut。导出失败/close异常/ACK未知均不发200。

close_timeout_ns由固定预算，推荐MODEL用300秒；截止采用实际monotonic，不用UTC推间隔，SDK客户端60秒超时不等于server已关。超时503+session UNKNOWN/instance DRAINING，保留活票据与资源直到真实退出；截止只限制等待，不kill/假worker_count=0/补seal或成功cut。controller所有保全任务仍有归属，服务不能报告clean STOPPED。重复DELETE：仍活CLOSING/UNKNOWN返回409/503；已CLOSED只能从保留已知cut/barrier验证返回同一成功状态，不再次terminate/write/close。无有效session404。关闭原因有限DELETE、SERVICE_STOP、IDLE；异常EOF、transport失败、非批准强停进入UNKNOWN，不推正常DELETE成功。

SERVICE_STOP先DRAINING，再全部session同屏障，最后ledger.close INSTANCE_END读回且group/catalog/allocator实际关闭；有active不能强close。SERVICE STOPPED只由真实进程退出/SCM及外部独占读回另证。SDK默认idle None；若启用idle只controller经同屏障，禁止manager私有idle提前删表当成功。监听关闭与writer关闭分别记录。日志不含令牌、异常敏感正文。关闭时连接exit_stack现SDK5秒shield且吞异常，必须改内部可观测严格清理适配，不以其正常返回证明cleanup成功。

## L8 已存在transfer异步线程/子进程的必要闭包

失败诊断另件不是成功sidecar：顶层exact6 {schema_version,kind=`pc026-observation-failure-v1`,run_id,capture_ref,rows,status=`FAILED`}；row exact4 {location,classification,reason,attempt_sequences}，location沿实际rawjoin定位结构；未invoked report定位为{report_call_sequence}单字段，不造raw。classification有限PRE_OBSERVER_REJECT、DUPLICATE_REJECT、ACCEPT_UNKNOWN、ACCEPTED_FAILED、ACCEPTED_COMPLETE_WITH_WIRE_ERROR、NOT_INVOKED、UNCLASSIFIED；reason有限AUTH/HOST/ORIGIN/BODY/PROTOCOL/INVALID_REQUEST/SESSION/CLOSING/DRAINING/ATTEMPT_LIMIT/ACTIVE_LIMIT/SEEN_LIMIT/BYTE_LIMIT/DUPLICATE/BEGIN_UNKNOWN/ACK_UNKNOWN/JOURNAL_UNKNOWN/CLOSE_UNKNOWN/WIRE_ERROR/NOT_INVOKED/UNCLASSIFIED。每raw occurrence逐一唯一分类：证据充分才填真实attempt seq；重复相同typedid从连续BEGIN及raw请求次序/真实拒响应对应，若并发不可唯一归属则UNCLASSIFIED，不能猜一accept对应两raw。门前和耗尽后无序号；全部raw拒绝只限实际capture有限全集，不宣称无限网络attempt全账。缺证分类不产生成功coverage/假accept。

## C6 有限预算及资源预留

lifecycle budgets exact16（strict positive int，无bool）：max_sessions、max_sdk_work、max_binary_work、max_pending_work、max_request_body_bytes、max_export_files、max_export_bytes、max_export_directories、max_cut_bytes、max_proof_bytes、max_source_manifest_bytes、max_maintenance_calls、max_maintenance_bytes、max_retained_state_bytes、close_timeout_ns、min_free_bytes。SDK parse/body及backend内存另有原门，不能称这些是总RSS保证；lifecycle票据/永久seq/seen+snapshot内存计真实字节并测对象峰值，达到门转DRAINING，不能释放旧exact6 events。

沿正式ledger：A=max_attempts、R/B/T=request codec、C=catalog record bytes、M=max_active；现最小归档门(3A+2)C+AT+MB+C，目录A+2，final record files 3A+2+AR。retained event canonical保守A(R-2)B，非RSS。MODEL8/2/10/4096/40960/4096得446464 bytes、106 final files、262144 event bytes；旧4GiB/100000非足够资格。
