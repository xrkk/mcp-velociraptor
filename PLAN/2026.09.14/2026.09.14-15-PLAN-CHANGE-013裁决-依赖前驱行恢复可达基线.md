# PLAN-CHANGE-013 裁决记录：依赖前驱行锁定基线改为恢复可达形态

创建日期：2026-09-14（Asia/Shanghai）。性质：PLAN-CHANGE 候选登记 + 用户裁决采纳 + 实施记录。候选与障碍证据见 Logs/P05/wf-01a05d1d-p05/service-preparation-g2b/g3-ready-iterations-ledger.md（障碍判定节）。

## 候选与裁决

- 候选：恢复后依赖前驱行（admin_override=false 基础行）的锁定基线不可由现行验证器满足——旧谓词要求五字段全空，而恢复后 serve_url/filestore_path 恒非空（artifact 定义自带的声明元数据）；基础行物化态不在 datastore 持久层，唯二满足路径（上游再物化=违反公网零请求；伪装本地转换=发明未评审状态）均不可行。
- 两个方向：(i) 接受恢复可达原生态并修订验证器前驱谓词；(ii) 裁决一处本地再物化路径。
- **用户裁决：采纳方向（i）。**

## 实施内容（本记录同轮完成）

`tests/p05_ready_evidence.py` 前驱谓词收窄为：身份三元组（artifact/filename/serve_locally 与锁定表逐项相等）+ `materialize is False` + version/hash/invalid_hash **必须为空** + serve_url/filestore_path **必须为非空字符串**。移除的是对"五字段全空"的历史偶态钉死，保留并强化了前驱=未物化定义态的可判别性（materialize/version/hash 三重否定断言）。

`tests/test_p05_ready_evidence.py`：合成前驱载荷改为恢复可达形态（version/hash/invalid_hash 空，serve_url/filestore_path 非空，serve_locally 工具用本地 public URL、etl2pcapng 用上游声明 URL）；新增负例 `test_rejects_predecessor_row_that_is_materialized_or_versioned`（materialize=True、非空 version、非空 hash、空 serve_url 四种变体均必须拒绝）。

## 范围与不变量

- 不变：override 行对 manifest 逐字段钉死、local_public_bytes（URL/size/sha256）与 locked_files 验证、artifact 定义金样、每工具恰一前驱一目标分组——一字未动。
- 证据力论证：override 行存续即 datastore 连续性证明；工具字节可解析性由 local_public_bytes（采集器实测拉取+哈希匹配、验证器独立复算）覆盖；前驱行空 version/hash 无安全语义。
- 受影响稳定边：P05 依赖验收条目（IMP/ACC-P05 依赖相关）与 ready 验证器及其测试切片；P06 经 activation validator 间接消费，内部变更不可见。
- 后续门：本变更并入待重过 Windows 代码门清单（安装器/启动器/采集器/prep/验证器/其测试）。

## 遗留（已裁决并实施）

dependencies 的 **probe 子句**同根因（per-boot 工具注册表恢复后为空，`inventory_get` 三变体实测 null、`tools()` 空）。**用户裁决：采纳（A）**——接受恢复可达形态：probe_rows 照实记录 Item=null 原件，验证器在 local_public_bytes 独立验证（URL 形式正则 + size/sha256 钉死 manifest，已实测通过）的前提下接受 Item=null；**非空 Item 保留全部原有严格身份断言**（新增负例：非空但错哈希仍拒绝）。替代方案（B）业务预热、（C）重复 inventory_add、（D）无副作用预热 API 均被否（顺序颠倒/破坏分组/不存在）。

同轮顺带的纯实现修正（非门变更）：验证器"public URL 摘要==内容 sha"为从未对过真实数据的前提——实测 URL 摘要是 server 内部 filestore 键（`public/<定义期望摘要>` 服务的字节哈希恰为锁定 sha，`public/<内容sha>` 为 404）；URL 等值断言改为本地 public 形式正则，哈希级保证不变。

## 结果

两项裁决落地后，十二类 ready 于 run-g3-ready-b72c3d52cd 首次在真实原件上全量通过 `verify_ready_raw_evidence`（详见 g3-ready-iterations-ledger.md 终态更新）。本变更涉及文件：tests/p05_ready_evidence.py、tests/p05_ready_collect.py、tests/test_p05_ready_evidence.py、tests/p05_prepare_fixtures.ps1、tests/p05_process_parent.py——全部并入待重过 Windows 代码门清单。

## 推论实施（probe 移除，零公网不变量修复）

G4.A 前置调查发现：采集器的 `inventory_get(tool=…, probe=TRUE)` 语义为**向上游 URL 发起实际探测请求**——etl2pcapng 前驱行上游为 GitHub releases，导致每次 ready 采集都从 server 发起一次公网请求（实测 Established 连接 185.199.108.153:443 为证；inventory 未被改动）。此为对"原始公网来源零请求"的主动违约，且 PC-013-A 已裁定 probe 无证据价值。处置（PC-013-A 推论）：采集器移除探针调用、载荷与验证器移除 probe_rows 子句、fixture 同步。修复后实测：完整 ready 采集全程 velociraptor 进程公网连接数为 **0**（前后快照对照），采集仍全量通过（run-g3-ready-e6ec415677）。
