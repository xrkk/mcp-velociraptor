## 3. 本批代码和证据的独立结果

### 3.1 源码检查

新 `tests/p06_evidence.py` 会拒绝绝对路径、反斜杠路径、`..`、符号链接/reparse point 和非普通文件；`verify_restore()` 要求恰好六类恢复记录，复算原始字节 SHA-256，且把 canonical 原文哈希与声明值、JSON 语义、activation evidence、快照/标记/主机名绑定一并检查。`verify_observation()` 对复制入报告包的 `server-observation.json` 做字节哈希和服务身份/时间检查。

`p06_aggregate_reports.py` 递归包哈希现会枚举普通文件、拒绝链接及特殊节点，并把恢复原件纳入 `@restore/<path>:<sha256>`；账本身份新增恢复证据、服务实例/PID/启动时间/观察、runner PID、会话生命周期和 `received_at`。`scenario_runner.py` 在 P06 正式 HTTP 前验证恢复根，并在完成后把观察原始字节复制进运行目录。四个新增负向单测覆盖缺原件、伪 canonical、观察摘要变异和嵌套包文件。

这些实现方向正确，特别是防止只信摘要或只哈希顶层目录；但单测 fixture 是新构造的合成记录，不能证明历史记录已经迁移为合规记录，也不能把校验器“拒绝旧记录”误报为 P06 成功。

## 4. CHK-024～027 状态

### CHK-024：未关闭

已验证新代码对 canonical 原始字节、六类恢复记录、路径安全、递归包哈希和观察摘要均增加了实质性校验；实际 r2 恢复根和既有 selected reports 却不能通过。`Logs/P06/recovered-r4reg-20260913T105946Z/manifest.json` 已把 14 个 r4reg 文件从正确目标回传并逐文件哈希，这只证明当前找回的字节；其自身限定也明确不绑定历史 HEAD 或原始执行时间。没有一个新、不可变、满足原件路径/哈希/语义/账本字段/观察原件的正式 P06 epoch，故 CHK-024 保持未关闭。

### CHK-025：未关闭

本批未改变资源资格代码或把资源门/拓扑/deadline 接入 `scenario_runner`。既有 `p06_resource_qualification.py` 仍是 stdio 资格路径；没有从 Snapshot 186 经外部官方 HTTP 到目标 `192.168.204.232:28790` 的资格证据，也没有逐大步骤资源阈值、deadline、失败处置的原始记录。回环 fixture 与控制 VM 的配置都不能替代总纲规定的正式链路。故 CHK-025 保持未关闭。

### CHK-026：未关闭

`tests/p07_cost_measurement.py` 未修改（HEAD/blob 与核验时一致）。`current_equivalent_chains` 仅有 calls、`poll_attempts`、bytes，欠缺当前侧 elapsed、与 upstream 的逐项 delta、固定任务原始输出/文件结果对照。`poll_attempts` 是尝试总数而非可审计的 retries；upstream 记录仅两条 wire call（合计 5.188、647 bytes），缺逐 retry transcript 和可比结果文件。资料虽声称内部 retry，数据不能支持该声明。P07 整体 totals 也不能替代 P07 §4.2 要求的固定任务双边口径。故 CHK-026 保持未关闭。

### CHK-027：未关闭

旧 `2026.09.13-05` 的“13/13 all green / CHK 已关闭”结论不能被后来回收的字节或本批 107 项局部回归追认。新回归确有价值，但绑定的是固定 HEAD 加四个未提交工作树 blob，且实施方自己保留了首批失败/skip 并声明不是 formal P06。加之 CHK-024～026 的正式证据仍缺，尚不存在能支持最终接受声明的新全阶段证据。故 CHK-027 保持未关闭。
