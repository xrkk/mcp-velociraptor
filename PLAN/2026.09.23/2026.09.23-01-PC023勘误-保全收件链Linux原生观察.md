# PC023 勘误：保全收件链 collector 改为 Linux 原生观察

2026-09-23。角色：勘误采纳记录（用户同日裁决"方案C"）；不是独立核验，不产生或关闭AUD/CHK。

## 事实与冲突

PC020 恢复前保全链（P05 v19 §4.1 preparation `preservation_manifest`）的收件端点固定 `http://192.168.204.1:28786/`（host 的 vmnet8 接口，VM 外保全语义正确）；但 `receiver_stopped` 观察的固定 argv 为 `powershell.exe -NoProfile -Command <Get-NetTCPConnection…>` 且要求观察机本地持有 `192.168.204.1`——预设收件主机是 Windows。现实 `.1` 在 Linux host 上，该 argv 不可执行。历史 R04（2026-09-20）隔离验证通过 HTTP seam 把网络落点映射到 owned `127.0.0.1` 动态端口，从未真实执行收件端观察；G13 首次真实执行暴露冲突（`.tmp/velo-glm-20260922-082250/G13-blocked-preservation-receiver.md`）。

## 勘误内容（方案 C，用户裁决采纳）

1. 收件端点**不变**：`http://192.168.204.1:28786/`，receiver 服务由 host 上临时 Python HTTP 服务承担，单文件请求后即停。
2. `receiver_stopped` 观察 collector 改为**收件主机本地 Linux 原生命令**：`/usr/bin/python3 -c <collector脚本>`；脚本从 `/proc/net/fib_trie` 提取本机全部 IPv4（必须含 `192.168.204.1`）、从 `/proc/net/tcp{,6}` 检查 28786 监听（十六进制端口 `7012`、状态 `0A`），输出与旧形状**完全一致**的 JSON（`schema_version/observer_ipv4/endpoint/interface_ipv4/rows`）。验证器的 stdout 校验谓词（.1 身份、rows 空＝监听已停）**不变**。
3. `RECEIVER_OBSERVER.operating_system` 由 `windows` 改为 `linux`；其余身份字段（scope/ipv4/endpoint）不变。
4. 不改变：传输命令（guest PowerShell 发送端）、收据/控制响应形状、included 恰一对象、seam 语义（测试 seam 改为纯文档构造，不再经 powershell 执行包装）。

## 不变义务

- 保全语义（VM 外、非秘密、排除凭据）不变；不新增任意端点；receiver 生命周期仍为"传输后停止并观察停止"。
- P05 v19 §4.1 正文对 receiver_stopped 的要求（"proves permitted evidence arrived with matching bytes and the temporary receiver is no longer reachable"）本就不锁观察命令具体形态，本勘误与其一致。
- 历史 Windows collector 原件形状保留为历史可读，不得冒充 Linux collector 新成功。
