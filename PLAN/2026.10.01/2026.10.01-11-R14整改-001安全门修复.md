# R14 整改之一：CHK-R14-001 /chunkbin Host/Origin 安全门

日期：2026-10-01。来源：`PLAN/2026.10.01/2026.10.01-10-独立核验-R14不通过.md` CHK-R14-001（编号身份 `c52638147a424519e9458fa1d58190a11fe78d9e#CHK-R14-001`）。

## 0. 缺陷与修复

**缺陷**：`build_formal_http_app` 把 `/chunkbin` 路由追加到 SDK 应用的路由表，但 SDK 的 `TransportSecuritySettings`（Host/Origin 校验）只在其自己的 streamable-HTTP 路由处理器内部执行（`mcp/server/streamable_http.py:465`），追加路由完全绕过；外层只有 Bearer 门。核验方本机与 `.232` 现场均证实：错误 Host/Origin 时 `/mcp` 421/403 而 `/chunkbin` 200。

**修复**（本提交）：新增 `HostOriginGate` 纯 ASGI 中间件，语义与 SDK 完全一致——Host 缺失或不允许 → 421 `Invalid Host header`；Origin 存在且不允许 → 403 `Invalid Origin header`；Origin 缺失放行；支持 `host:*` 通配；不做其他归一化。注册为最内层中间件，覆盖**全部** HTTP 路径：`/chunkbin` 在进入端点、读体、业务调用前过门；`/mcp` 的 Bearer-first 拒绝顺序不变（门在最内层，SDK 路由内部仍保留其原校验，二者设置相同、行为一致）。

## 1. 测试（CHK 最小闭合的本地部分）

新增 `tests/test_transport_host_origin_gate.py`（14 项全过）：

- 单元（裸 ASGI 探针，记录 handler 是否执行）：正确 Host 无/有 Origin 通过；Host 缺失/错误 → 421 且 handler 未执行；Origin 不允许 → 403 且 handler 未执行；通配命中通过、通配不命中仍拒；非 http scope 直通。
- 接线（`build_formal_http_app` ＋桩 SDK 服务器）：`/chunkbin` 错误 Host → 421 且无 VBT 帧（未达端点）；不允许 Origin → 403；Host 缺失 → 421；合法 Host 无 Origin → 200 且返回端点自身的 `invalid_arguments` VBT 帧（证明到达端点）；Bearer 仍为最外层（坏 Host＋坏 Bearer → 401）；`/mcp` 保持 421/403/200 行为。

相邻回归：`test_p02_transport`＋`test_service_transport_lifecycle`＋`test_transfer_mcp` 34 passed / 7 skipped；`test_transfer_binary_channel` 连续 5 轮 4 passed（其间出现的单次失败与核验记录 §7 观察一致，为本就登记的偶发竞态，stash 对照与重复运行确认与本次改动无关）。
